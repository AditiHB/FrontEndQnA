# 23. Service Workers & PWA

> **Like I'm 5:** A PWA is an app you can put on your phone's home screen, and it still opens without internet. A service worker is a helper that keeps copies of things so the app works offline.

> **Learn it by doing:** build this step by step in the tutorial: [Chapter 29: Progressive web apps and service workers](../tutorial/29-pwa.md).

## Key concepts
- A **service worker** is a script that runs in the background, intercepts network requests, and caches responses.
- A **Progressive Web App (PWA)** is a web app that can be installed, works offline, and sends push notifications.
- Angular provides `@angular/service-worker`, configured with `ngsw-config.json`.

## Adding PWA support

```bash
ng add @angular/pwa
```

This adds the manifest, icons, the service worker registration, and `ngsw-config.json`.

## Registration

```ts
// app.config.ts
import { provideServiceWorker } from '@angular/service-worker';

export const appConfig = {
  providers: [
    provideServiceWorker('ngsw-worker.js', {
      enabled: !isDevMode(),
      registrationStrategy: 'registerWhenStable:30000',
    }),
  ],
};
```

## Caching configuration

```json
{
  "assetGroups": [
    {
      "name": "app",
      "installMode": "prefetch",
      "resources": { "files": ["/index.html", "/*.js", "/*.css"] }
    },
    {
      "name": "assets",
      "installMode": "lazy",
      "updateMode": "prefetch",
      "resources": { "files": ["/assets/**"] }
    }
  ],
  "dataGroups": [
    {
      "name": "api",
      "urls": ["/api/**"],
      "cacheConfig": { "strategy": "freshness", "maxSize": 100, "maxAge": "1h", "timeout": "5s" }
    }
  ]
}
```

- `performance` strategy: cached first, fast.
- `freshness` strategy: network first, falls back to cache. Good for API data.

## Handling updates

```ts
import { SwUpdate, VersionReadyEvent } from '@angular/service-worker';

private swUpdate = inject(SwUpdate);

constructor() {
  if (this.swUpdate.isEnabled) {
    this.swUpdate.versionUpdates
      .pipe(filter((e): e is VersionReadyEvent => e.type === 'VERSION_READY'))
      .subscribe(() => {
        if (confirm('A new version is available. Reload now?')) location.reload();
      });
  }
}
```

## Push notifications

```ts
private swPush = inject(SwPush);

subscribe() {
  this.swPush.requestSubscription({ serverPublicKey: VAPID_PUBLIC_KEY })
    .then(sub => this.api.saveSubscription(sub));
}
```

## Offline behavior
- Show an offline banner using `navigator.onLine` and the `online` / `offline` events, or an RxJS `fromEvent` stream.
- Queue writes locally (IndexedDB) and sync when the connection returns, for critical flows.

## Gotchas found while building the tutorial's Toy Shop
- **With SSR, the app's entry file is `index.csr.html`**, not `index.html`. Set `"index": "/index.csr.html"` in `ngsw-config.json`, or the offline page can be blank.
- The service worker is only generated by a **production** build (`"serviceWorker": "ngsw-config.json"` in the production configuration), so test it with the built server, not `ng serve`.
- **Never let `ngsw.json` and `ngsw-worker.js` be cached for long.** The server that Angular generates caches every static file for a year by default, which would stop browsers from ever finding a new version. Send `Cache-Control: no-cache` for everything that has no fingerprint in its name ([34](34-cicd-and-deployment.md)).
- In unit tests, provide a switched-off worker: `provideServiceWorker('ngsw-worker.js', { enabled: false })`, or a fake `SwUpdate`.
- Use a data group with `strategy: "freshness"` and a `timeout` for API data that should be fresh when possible but available offline.

## Important points
- Service workers only work over HTTPS (localhost is an exception for development).
- Caching bugs are hard to debug. Use a versioned build hash, and test the update flow.
- Do not cache sensitive authenticated responses in a shared cache.
